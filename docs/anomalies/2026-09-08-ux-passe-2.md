## ANO-UX-006 — Chevauchement dans le formulaire « Départ anticipé » (apprenant)

| Champ | Contenu |
|---|---|
| **Identifiant** | ANO-UX-006 |
| **Écran** | `/my-attendance/early-departures` — carte « Signaler un départ » (`my-early-departures.html`) |
| **Symptôme** | L'aide (`mat-hint` « Visible sur votre planning. ») du premier champ chevauche le libellé flottant « Heure de départ » du champ suivant. |
| **Cause réelle** | Le formulaire était un `<form>` nu (aucun rythme vertical entre les `mat-form-field` empilés) **et** chaque champ portait `class="att__field"` dont la règle `display: block` **écrasait la mise en page interne du `mat-form-field`** (`inline-flex; flex-direction: column`). Cet écrasement supprimait la hauteur réservée par `.mat-mdc-form-field-subscript-wrapper` sous le premier champ : son `mat-hint` se superposait au `mat-label` du champ suivant. Défaut **local** — aucune règle globale en cause, `subscriptSizing` par défaut (`fixed`) était correct. |
| **Correction** | `FIXED_LOCAL` (8 sept.). Le formulaire s'appuie sur la primitive partagée `.esic-form` (colonne flex + `gap: --esic-space-3`), l'action passe dans `.esic-form__actions`. La classe `att__field` et sa règle `display: block` sont supprimées (usage unique, vérifié). Aucune modification métier, aucun `overflow: hidden`, aucun positionnement absolu, aucune retouche globale des `mat-form-field`. |
| **Tests** | `my-early-departures.spec.ts` +2 : le `<form>` porte `.esic-form`, plus aucun `.att__field`, les 3 `mat-form-field` portent chacun un `.mat-mdc-form-field-subscript-wrapper`, le libellé « Heure de départ » est rendu ; la table « Mes signalements » porte la primitive compacte. Suite front complète **929 / 0**. |
| **Reste à vérifier** | Rendu réel desktop / tablette / mobile / zoom 200 % au navigateur — `NOT_PERFORMED` (jsdom ne met pas en page). |

## ANO-UX-007 — Chiffres d'assiduité incohérents au tableau de bord / à la synthèse

| Champ | Contenu |
|---|---|
| **Identifiant** | ANO-UX-007 |
| **Écrans** | `/dashboard` (carte responsable « Taux d'assiduité », « Taux d'assiduité par classe »), `/attendance-management/summary`. |
| **Symptôme** | Taux affiché à `0 %` ou anormalement bas ; dénominateur (« demi-journées attendues ») visiblement gonflé. |
| **Cause** | **Non ré-instruite dans cette passe** : déjà consignée. Le *rollup* du tableau de bord (`DashboardCardsService`) compte des demi-journées « attendues » sur **chaque jour d'alternance `SCHOOL` même sans séance publiée** (dénominateur gonflé), et le calcul est fait en Java plutôt qu'en SQL (`CURRENT-STATE.md`, entrées des 6-7 sept. ; `docs/anomalies/2026-09-07-performance-ux.md` ANO-PERF-001/002 ; `2026-09-07-diagnostic-performance.md`). Le **rapport journalier canonique** (`GET /attendance/reports/daily`, `EF-ATT-004`) calcule correctement — la divergence est propre au rollup. |
| **Statut** | `DECLARED`. Le défaut est **backend / calcul métier**, pas frontend. Cette passe n'a **pas** maquillé les chiffres par du CSS et n'a **pas** entrepris la correction backend (non mesurée, exige `EXPLAIN ANALYZE` sur la Pi + cycle build/deploy — hors périmètre et hors d'atteinte cette session). La refonte visuelle (grille compacte, tableau fusionné) affiche les valeurs telles que l'API les renvoie. |
| **Correction attendue** | Borne de fenêtre d'agrégat + `GROUP BY` SQL + dénominateur restreint aux séances **réellement attendues** pour l'apprenant (cf. ANO-PERF-001 « Correction attendue »). Test de coût SQL borné + test de valeur : une classe sans séance publiée un jour `SCHOOL` ne gonfle pas le dénominateur. |

## ANO-UX-008 — Tableaux non « dans l'assiette » : paginator hors de vue

| Champ | Contenu |
|---|---|
| **Identifiant** | ANO-UX-008 |
| **Écrans** | Synthèse et rapports du suivi d'assiduité, tableau « Taux d'assiduité par classe », historique / suivi à distance de la fiche apprenant, « Mes signalements » de départ anticipé. |
| **Symptôme** | Pour atteindre la pagination d'un tableau, l'utilisateur doit faire défiler toute la page ; la molette, au-dessus du tableau, fait défiler la page et non le corps du tableau. |
| **Correction** | `FIXED_LOCAL` (8 sept.). Nouvelle variante de primitive **`.esic-table-wrap--compact`** (`_primitives.scss`) : même mécanique que `.esic-table-wrap--tall` (entête `sticky`, défilement interne, `overscroll-behavior: contain`) avec un plafond calibré ~6-7 lignes (`--esic-table-max-h: clamp(15rem, 42vh, 24rem)`, surchargeable inline pour ~5 lignes). Le paginator reste **hors** de l'enveloppe défilante, juste dessous, donc toujours visible sans second défilement. Aucun gestionnaire `wheel` en JS ; clavier / PageUp-Down / lecteur d'écran intacts ; défilement horizontal mobile conservé ; les petites tables gardent leur hauteur naturelle (`max-height`, jamais `height`). Opt-in explicite. |
| **Écrans traités** | `attendance-summary` (tableau fusionné), `attendance-report` **conserve** `--tall` (rapports potentiellement longs), `student-profile` (historique + suivi à distance), `my-early-departures` (« Mes signalements »). |
| **Limite connue** | `overscroll-behavior: contain` empêche le chaînage de la molette : au bord haut/bas du corps de table, la page ne défile pas tant que le curseur reste sur le tableau (comportement aligné sur `.esic-table-wrap--tall` déjà en place ; le curseur hors tableau défile la page normalement). |
| **Tests** | assertions de présence de la classe sur les enveloppes concernées (`student-profile.spec.ts`, `my-early-departures.spec.ts`). Rendu `sticky` réel au défilement : `NOT_PERFORMED` (jsdom). |
